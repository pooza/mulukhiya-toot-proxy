# ドキュメント棚卸し

⚠ **原則の正本は chubo2 の [docs/doc-maintenance.md](https://github.com/pooza/chubo2/blob/main/docs/doc-maintenance.md)**（配置の原則・昇格しないもの・頻度）。
このスキルはそれを回すための手順で、迷ったら向こうを読む。

⚠⚠ **「docs や Wiki の陳腐化を洗い出す」ことではない。**主眼は**メモリ → docs の再配置**
（2026-09-08 に取り違えて指摘された・[[feedback_doc-inventory-means-memory-to-docs]]）。
Wiki の更新はリリース手順 11 の仕事で、ここには混ぜない。
⚠ **chubo2 の Issue 棚卸し（同期手順 §6-2・30 日ごと）とも別物。**あちらは open Issue の生死、こちらは知見の置き場所。

## なぜ要るか

インフラ作業は mulukhiya・chubo2・mastodon・misskey・makoto2 のセッションに分かれて依頼される。
**メモリはプロジェクトごとに分かれていて共有されない**ので、片方にだけ事実が残ると、
もう片方は同じ調査を一からやり直す。docs（git）だけが全セッションから読める。

## 1. 候補を絞る（grep で・目視で「たぶん書いてある」と判断しない）

```sh
python3 .claude/skills/doc-inventory/scripts/memory_vs_docs.py
```

- 既定の対象は、**`infra-note.md` の「最終ドキュメント棚卸し」の日付より後に更新されたメモリ**。
  プロジェクトは mulukhiya-toot-proxy・chubo2・makoto2・mastodon・misskey（`--all-projects` で全部）
- 出力は「docs に無い語の数 / 語の数」。**未記載の語が多い P（project・reference）から読む**
- 気になるメモリは `--terms <プロジェクト>/<ファイル>` で、description と docs に無い語を出す
- ⚠ メモリの置き場は Drive への symlink。`ls <dir>/memory` だと中身が見えないことがある（スクリプトは辿る）
- ⚠ docs の `infra-note.md` だけを見ない。本体は `infra-*.md` に分かれている（スクリプトは `docs/*.md` 全体を見る）

## 2. 1 件ずつ判断する

**昇格する**（他のセッションが知らないと困る事実）:
- 機械・サービスの現況、手順、再発する罠 → `infra-note.md` 冒頭の索引で行き先のファイルを決め、その節へ
- 日付のある出来事（適用・障害・切り替え） → `infra-history.md`（新しいものが上・日付の順に差し込む）
- デプロイの直前に見ること → `infra-mastodon.md` / `infra-misskey.md` の「デプロイ手順」

**昇格しない**:
- 進め方の好み、提案の抑制（「〇〇を勧めない」）、私的な判断、作業ルール（シェルの癖・返答の言語など）
- アプリやフォークの開発の手順（mastodon の 5.0 の検証、misskey の lint の回し方、makoto2 の設計）。
  それぞれのリポジトリの docs の仕事で、chubo2 のインフラ文書ではない
- Issue / Releases が正本のもの（複写しない）

2026-11-22 の実施では、66 件のうち昇格は 3 件だった
（inori の機械まわり・Mastodon フォークの #1007/#1011 の適用・vulcan の実況中の確かめ方）。**少なくて正常。**

⚠ **別セッションが既に昇格していることが多い**（chubo2 セッションは自分で docs に書く）。
語が docs に無くても、節を開くと同じ事実が別の言い回しで書いてあることがある。差分だけを足す。

## 3. docs の古い記述を直す（ついでに・裏取りしてから）

```sh
cd ~/repos/chubo2/docs && grep -n -E "未構築|準備中|移行中|未着工" infra-*.md | grep -v infra-history
```

- 完了した移行が「予定」のまま、切り替え前の現況が「いまの形」として書かれていないかを見る
  （2026-11-22 は「無人で回す」の冒頭が Mac の launchd のままだった）
- **実機・レシピ・GitHub で裏取りしてから直す。**推測で断定しない
- 経緯として残す価値のある古い記述は消さずに「経緯」として短くするか、`infra-history.md` へ

## 4. 仕上げ

- `infra-note.md` 冒頭の「**最終ドキュメント棚卸し**」を当日にする（昇格が 0 件でも更新する）
- chubo2 の `docs/` は **main へ直接コミットしてよい**（記録はレビュー対象ではない）。レシピは従来どおり PR
- ⚠ chubo2 の作業ツリーは別セッションと共有している。コミットの前に `git status` で自分の変更だけかを見る
- **昇格したメモリは消さず、先頭に正本へのポインタを 1 行足す**（メモリは git 管理外で、消すと戻せない）。
  別セッションのメモリでも同じ。古くなった記述に気づいたら、その行に「古い」と正しい事実への参照を書く
- 結果はユーザーに「昇格した件数と行き先・直した古い記述・見送ったものの理由」で報告する
